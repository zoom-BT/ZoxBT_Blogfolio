## Introduction

L'**overfitting** et l'**underfitting** sont deux problèmes fondamentaux en Machine Learning qui peuvent ruiner les performances de vos modèles. Comprendre ces concepts est essentiel pour tout praticien du ML.

## Qu'est-ce que l'Overfitting?

### Définition

L'overfitting se produit quand un modèle:
- Apprend **trop bien** les données d'entraînement
- Mémorise le bruit et les détails spécifiques
- **Généralise mal** sur de nouvelles données

### Analogie

Imaginez un étudiant qui **mémorise** les réponses d'un examen précédent au lieu de **comprendre** les concepts. Il réussira parfaitement cet examen spécifique, mais échouera face à de nouvelles questions.

### Signes d'Overfitting

```python
# Exemple typique d'overfitting
Training Accuracy: 99%
Validation Accuracy: 65%
# Grand écart = overfitting!
```

### Visualisation

```
Performance
    │
100%│         ╱───── Training
    │        ╱
    │       ╱
    │      ╱
 50%│     ╱  ╱─╲ Validation
    │    ╱  ╱   ╲
  0%└────────────────> Complexité du modèle
```

## Qu'est-ce que l'Underfitting?

### Définition

L'underfitting arrive quand un modèle est:
- **Trop simple** pour capturer les patterns des données
- Incapable d'apprendre même les relations basiques
- Mauvais sur les données d'entraînement ET de test

### Analogie

Un étudiant qui n'a pas étudié du tout et répond au hasard.

### Signes d'Underfitting

```python
# Exemple d'underfitting
Training Accuracy: 60%
Validation Accuracy: 58%
# Les deux sont faibles = underfitting!
```

## Causes de l'Overfitting

### 1. Modèle Trop Complexe

```python
# Réseau de neurones avec trop de couches
model = Sequential([
    Dense(1000, activation='relu'),
    Dense(1000, activation='relu'),
    Dense(1000, activation='relu'),
    Dense(1000, activation='relu'),
    Dense(1000, activation='relu'),  # Trop de paramètres!
    Dense(1, activation='sigmoid')
])
```

### 2. Pas Assez de Données

Ratio paramètres/données déséquilibré:
- 1 million de paramètres
- 1 000 exemples d'entraînement
- ⚠️ Problème garanti!

### 3. Entraînement Trop Long

```python
# Trop d'epochs
model.fit(X_train, y_train, epochs=1000)  # Oups!
```

## Solutions à l'Overfitting

### 1. Régularisation L1/L2

```python
from tensorflow.keras import regularizers

model.add(Dense(64,
    kernel_regularizer=regularizers.l2(0.01),
    activation='relu'
))
```

**Comment ça marche:**
- Pénalise les poids trop grands
- Force le modèle à rester simple
- L1: pousse vers la sparsité
- L2: réduit l'amplitude des poids

### 2. Dropout

```python
from tensorflow.keras.layers import Dropout

model.add(Dense(128, activation='relu'))
model.add(Dropout(0.5))  # Désactive 50% des neurones
model.add(Dense(64, activation='relu'))
model.add(Dropout(0.3))
```

**Principe:**
- Désactive aléatoirement des neurones
- Force la redondance
- Rend le modèle plus robuste

### 3. Early Stopping

```python
from tensorflow.keras.callbacks import EarlyStopping

early_stop = EarlyStopping(
    monitor='val_loss',
    patience=10,
    restore_best_weights=True
)

model.fit(X_train, y_train,
          validation_data=(X_val, y_val),
          callbacks=[early_stop],
          epochs=1000)
```

### 4. Data Augmentation

```python
from tensorflow.keras.preprocessing.image import ImageDataGenerator

datagen = ImageDataGenerator(
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    horizontal_flip=True
)
```

### 5. Plus de Données

Le meilleur remède:
- Collecter plus d'exemples
- Utiliser des données synthétiques
- Transfer learning si impossible

## Solutions à l'Underfitting

### 1. Modèle Plus Complexe

```python
# De trop simple...
model = Sequential([
    Dense(1, activation='sigmoid')
])

# À mieux adapté
model = Sequential([
    Dense(128, activation='relu'),
    Dense(64, activation='relu'),
    Dense(32, activation='relu'),
    Dense(1, activation='sigmoid')
])
```

### 2. Meilleurs Features

```python
# Feature engineering
X['age_squared'] = X['age'] ** 2
X['age_log'] = np.log(X['age'])
X['interaction'] = X['feature1'] * X['feature2']
```

### 3. Plus d'Epochs

```python
# Vérifier si le modèle converge
history = model.fit(X_train, y_train,
                   epochs=100,  # Augmenter si nécessaire
                   validation_split=0.2)

# Visualiser
plt.plot(history.history['loss'])
plt.plot(history.history['val_loss'])
```

### 4. Réduire la Régularisation

```python
# Trop de régularisation peut causer l'underfitting
# Réduire le coefficient
model.add(Dense(64,
    kernel_regularizer=regularizers.l2(0.001),  # Plus petit
    activation='relu'
))
```

## Le Compromis Biais-Variance

### Biais (Bias)
- Erreur due à des hypothèses trop simplistes
- **Underfitting** = biais élevé

### Variance
- Sensibilité aux fluctuations des données
- **Overfitting** = variance élevée

### Objectif
Trouver le **sweet spot**:

```
Erreur totale = Biais² + Variance + Bruit

Objectif: minimiser les deux premiers termes
```

## Workflow Pratique

### 1. Commencer Simple

```python
# Baseline simple
baseline = LogisticRegression()
baseline.fit(X_train, y_train)
print(f"Train: {baseline.score(X_train, y_train)}")
print(f"Test: {baseline.score(X_test, y_test)}")
```

### 2. Analyser les Résultats

```python
if train_score > test_score + 0.1:
    print("Overfitting détecté!")
elif train_score < 0.7:  # Seuil dépend du problème
    print("Underfitting détecté!")
```

### 3. Itérer

- Underfitting → Complexifier
- Overfitting → Régulariser
- Répéter jusqu'à convergence

## Techniques de Validation

### K-Fold Cross-Validation

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, X, y, cv=5)
print(f"Accuracy: {scores.mean():.2f} (+/- {scores.std():.2f})")
```

### Learning Curves

```python
from sklearn.model_selection import learning_curve

train_sizes, train_scores, val_scores = learning_curve(
    estimator, X, y, cv=5, n_jobs=-1,
    train_sizes=np.linspace(0.1, 1.0, 10)
)

# Visualiser
plt.plot(train_sizes, train_scores.mean(axis=1), label='Training')
plt.plot(train_sizes, val_scores.mean(axis=1), label='Validation')
```

## Checklist Pratique

- [ ] Monitorer train ET val loss

### Après l'Entraînement
- [ ] Évaluer sur le test set

## Cas Pratique: Exemple Complet

```python
import numpy as np
from tensorflow import keras
from tensorflow.keras import layers, regularizers
from tensorflow.keras.callbacks import EarlyStopping

# Données
(X_train, y_train), (X_test, y_test) = keras.datasets.mnist.load_data()
X_train = X_train.reshape(-1, 784) / 255.0
X_test = X_test.reshape(-1, 784) / 255.0

# Modèle bien équilibré
model = keras.Sequential([
    layers.Dense(128, activation='relu',
                kernel_regularizer=regularizers.l2(0.001)),
    layers.Dropout(0.3),
    layers.Dense(64, activation='relu',
                kernel_regularizer=regularizers.l2(0.001)),
    layers.Dropout(0.2),
    layers.Dense(10, activation='softmax')
])

model.compile(
    optimizer='adam',
    loss='sparse_categorical_crossentropy',
    metrics=['accuracy']
)

# Entraînement avec early stopping
early_stop = EarlyStopping(monitor='val_loss', patience=5)

history = model.fit(
    X_train, y_train,
    epochs=50,
    batch_size=32,
    validation_split=0.2,
    callbacks=[early_stop]
)

# Évaluation
test_loss, test_acc = model.evaluate(X_test, y_test)
print(f"Test accuracy: {test_acc:.4f}")
```

## Conclusion

### Points Clés à Retenir

1. **Overfitting:** Trop complexe, mémorise les données
2. **Underfitting:** Trop simple, n'apprend pas assez
3. **Solution:** Trouver le bon équilibre

### Règles d'Or

- Toujours séparer train/val/test
- Monitorer les deux metrics
- Commencer simple, complexifier graduellement
- Régulariser si nécessaire
- Collecter plus de données quand possible
